# اسکریپت مدیریت تونل معکوس SSH برای نودهای پاسارگاد

این پروژه جهت ایجاد، پایش زنده و مدیریت اتصالات تونل معکوس (Reverse SSH Tunnel) پایدار بین سرورهای ایران و خارج، به‌ویژه برای اتصال نودهای پنل پاسارگاد (Pasarguard) طراحی شده است.

این اسکریپت به‌صورت خودکار بر روی لینوکس نصب شده و دستور سیستماتیک `pg-tunnel` را در اختیارتان قرار می‌دهد.

---

## 🚀 نصب سریع (دستور یک‌خطی)

### الف) نصب مستقیم از شاخه اصلی (`main`)
برای نصب یا اجرای مستقیم نسخه منتشرشده در شاخه `main`، دستور زیر را در ترمینال سرور (با دسترسی `root` یا `sudo`) وارد کنید:

```bash
sudo curl -fsSL -H "Accept: application/vnd.github.raw+json" "https://api.github.com/repos/XiliService/pg-node-ssh-tunnel/contents/script.sh?ref=main" -o /usr/local/bin/pg-tunnel && sudo chmod +x /usr/local/bin/pg-tunnel && sudo pg-tunnel
```

### ب) نصب مستقیم از شاخه نشست کاری یا کامیت دلخواه (بدون نیاز به PR و Merge)
برای دریافت مستقیم آخرین کامیت یک شاخه کاری (مثلاً `arena/...`) بدون نیاز به ساخت Pull Request یا Merge در `main`، کافیست مقدار `BRANCH` را قرار داده و اجرا کنید:

```bash
BRANCH="arena/3db13c2c-pg-node-ssh-tunnel" && sudo mkdir -p /etc/pg-tunnel && echo "$BRANCH" | sudo tee /etc/pg-tunnel/update_ref.conf >/dev/null && sudo curl -fsSL -H "Accept: application/vnd.github.raw+json" -G --data-urlencode "ref=${BRANCH}" "https://api.github.com/repos/XiliService/pg-node-ssh-tunnel/contents/script.sh" -o /usr/local/bin/pg-tunnel && sudo chmod +x /usr/local/bin/pg-tunnel && sudo pg-tunnel
```

پس از اولین اجرا، اسکریپت روی سرور ثبت شده و در دفعات بعدی فقط کافیست دستور زیر را بزنید (و برای بروزرسانی‌های بعدی مستقیماً از **گزینه ۶ منو** استفاده کنید):
```bash
pg-tunnel
```

## 📌 راهنمای استفاده سریع

### ۱. تنظیم سرور ایران
1. اسکریپت را با دستور `pg-tunnel` اجرا کنید.
2. گزینه `1` (`Install / Configure Tunnel`) و سپس گزینه `1) Iran Server` را انتخاب کنید.
3. اطلاعات زیر را وارد کنید:
   - **آی‌پی سرور خارج** (آی‌پی خروجی سرور خارج که در پاسارگاد ثبت شده).
   - **پورت‌های دیتا** (با کاما جدا شده، مانند: `64483,26132,22971`).
   - **پورت SSH ثانویه دلخواه** (مثلاً `2222` یا `8543`).

### ۲. تنظیم سرور خارج
1. اسکریپت را در **سرور خارج** اجرا کنید.
2. گزینه `1` را زده و سپس `2) Foreign Server` را انتخاب کنید.
3. اطلاعات زیر را وارد کنید:
   - **آی‌پی سرور ایران**.
   - **پورت SSH ثانویه سرور ایران** (همان پورتی که در مرحله قبل تعریف کردید).
   - **پورت مدیریت نود** (مانند: `62075`).
   - **پورت‌های دیتا** (همان پورت‌های مرحله قبل).
4. رمز عبور سرور ایران را یک‌بار وارد کنید تا کلید SSH به‌صورت خودکار منتقل شده و سرویس دائم تشکیل شود.

### ۳. پایش زنده ترافیک مصرفی و سرعت لحظه‌ای (گزینه `2`)
با انتخاب گزینه `2` (`Check Status / Rules`):
- **حجم مصرف‌شده آپلود، دانلود و مجموع ترافیک** با تبدیل خودکار واحد به **`MB`** یا **`GB`** نمایش داده می‌شود.
- **سرعت لحظه‌ای دانلود و آپلود** بر حسب **`MB/s`** (مگابایت بر ثانیه) هر **۱ ثانیه به‌صورت زنده** بروزرسانی می‌شود.
- با فشردن کلید `Enter` یا `q` بلافاصله به منوی اصلی بازمی‌گردید.

### ۴. بروزرسانی هوشمند بدون نیاز به PR و Merge (گزینه `6`)
با انتخاب گزینه `6` (`Update Script`):
- اسکریپت ابتدا آخرین نسخه موجود در شاخه `main` گیت‌هاب را بررسی و با نسخه فعلی مقایسه می‌کند.
- اگر نسخه `main` جدیدتر از نسخه فعلی باشد، خودکار همان نسخه را نصب می‌کند.
- **اگر نسخه شاخه `main` پایین‌تر یا برابر با نسخه فعلی باشد**، از شما **نام شاخه نشست کاری** (مانند `arena/...`) یا **هش کامیت (Commit SHA)** را دریافت می‌کند، آخرین کامیت لحظه‌ای آن شاخه را از طریق GitHub API استخراج کرده و بدون معطلی کش CDN و **بدون نیاز به PR یا Merge** آخرین نسخه اسکریپت را جایگزین و اجرا می‌کند (نام آخرین شاخه واردشده نیز برای دفعات بعد در `/etc/pg-tunnel/update_ref.conf` به خاطر سپرده می‌شود).

## 🤖 مستندات فنی و ساختار اسکریپت (مخصوص AI Agents و توسعه‌دهندگان)

> **توجه برای ایجنت‌های هوش مصنوعی (AI Agents):**  
> اگر در یک نشست جدید در حال توسعه یا اصلاح این مخزن هستید، لطفاً الزامات و ساختارهای زیر را کاملاً حفظ کنید تا عملکرد تونل، آمار مصرف ترافیک یا شبکه داکر سرورها مختل نشود.

### ۱. معماری و منطق کاری (Architecture)
* **پورت SSH ثانویه (Secondary SSH Port):**  
  اسکریپت پورت اصلی ۲۲ را **هرگز حذف نمی‌کند**. پورت ثانویه سفارشی (مثلاً ۲۲۲۲ یا ۸۵۴۳) فقط کنار پورت ۲۲ اضافه می‌شود تا تونل معکوس از طریق آن برقرار شود و اختلالات DPI روی پورت ۲۲، تونل را قطع نکند.
* **مدیریت SSH در اوبونتو (`ssh.socket` vs `ssh.service`):**  
  در توزیع‌های جدید اوبونتو، `ssh.socket` باعث خرابی لیسن کردن روی پورت‌های چندگانه و خطا در systemd می‌شود. اسکریپت به‌صورت اجباری `ssh.socket` را `mask` کرده و مستقیماً از `ssh.service` استفاده می‌کند.
* **ترافیک و بازهدایت iptables در ایران:**  
  سرور ایران ترافیک خروجی به سمت آی‌پی خارج را با رول زیر به پورت‌های لوکال‌بایند شده هدایت می‌کند:
  `iptables -t nat -A OUTPUT -p tcp -d OUT_IP --dport PORT -j REDIRECT --to-ports PORT`
  *⚠️ **قانون حیاتی:** هرگز نباید جدول NAT با دستور `iptables -t nat -F` پاکسازی (Flush) شود! این کار شبکه Docker و پل‌های شبکه پاسارگاد را می‌کشد. حذف رول‌ها باید حتماً به‌صورت Targeted با سوئیچ `-D` انجام شود.*

### ۲. شمارش دقیق و پایدار ترافیک تونل (Persistent Traffic Accounting)
* شمارش بایت‌ها از طریق دو زنجیره غیرفعال اختصاصی `PG_TUNNEL_IN` و `PG_TUNNEL_OUT` در جدول `iptables -t mangle` با هدف `-j RETURN` انجام می‌شود که هیچ بسته‌ای را تغییر نداده و هیچ تداخلی با Docker یا `nat` ندارد.
* وضعیت ترافیک به‌صورت اتمیک با قفل `flock` و محاسبات ۶۴ بیتی در `/etc/pg-tunnel/traffic.state` به همراه شناسه یکتای بوت کرنل (`/proc/sys/kernel/random/boot_id`)، سرویس `/etc/systemd/system/pg-tunnel-acct.service` و کران‌جاب همگام‌ساز `/etc/cron.d/pg-tunnel-acct` نگهداری می‌شود.
* **قانون ماندگاری داده:** آمار مصرف ترافیک با ریستارت سرویس‌ها، کران‌جاب خودکار (گزینه ۸)، تعمیر تانل (گزینه ۷)، ریبوت سرور یا بروزرسانی اسکریپت (گزینه ۶) **هرگز صفر نمی‌شود** و فقط در زمان حذف ایمن (گزینه ۳) یا نصب مجدد تانل (گزینه ۱) ریست می‌گردد.

### ۳. پایدارسازی سرویس در سرور خارج (Systemd Service)
سرویس `/etc/systemd/system/reverse-tunnel.service` روی سرور خارج ساخته می‌شود.  
پارامترهای کلیدی SSH در این سرویس عبارتند از:
- `-o ServerAliveInterval=30` و `-o ServerAliveCountMax=3`: جهت تشخیص قطعی اتصال و بازسازی آن.
- `-o ExitOnForwardFailure=yes`: در صورت اشغال بودن پورت، پروسه متوقف شده تا systemd آن را Restart کند.
- `Restart=always` و `RestartSec=8`: تلاش مجدد بی‌نهایت برای وصل ماندن تونل.

### ۴. ذخیره‌سازی کانفیگ‌ها و قابلیت Update / Repair
* کانفیگ‌ها در مسیر `/etc/pg-tunnel/iran.conf` و `/etc/pg-tunnel/foreign.conf` ذخیره می‌شوند.
* **گزینه ۶ (Update):** نسخه `SCRIPT_VERSION` را با شاخه `main` مقایسه می‌کند؛ اگر نسخه `main` پایین‌تر یا مساوی باشد، نام شاخه کاری یا هش کامیت را از کاربر گرفته، آخرین کامیت آن را از GitHub API استخراج کرده و بدون نیاز به PR/Merge مستقیماً جایگزین `/usr/local/bin/pg-tunnel` می‌کند.
* **گزینه ۷ (Repair):** بدون نیاز به دریافت مجدد IPها از کاربر، متغیرها را از فایل کانفیگ خوانده و سرویس‌ها را ریستارت و ترمیم می‌کند (بدون صفر کردن آمار ترافیک).

### ⚠️ الزامات سخت‌گیرانه برای توسعه‌دهندگان بعدی:
1. **زبان اسکریپت:** تمامی متون، پرامپت‌ها، لاگ‌ها و پیام‌های داخل اسکریپت `script.sh` باید **۱۰۰٪ انگلیسی** باقی بمانند.
2. **عدم قطع دسترسی:** از دستوراتی مانند `killall sshd` استفاده نکنید. ریستارت سرویس‌ها باید همیشه از طریق `systemctl restart ssh.service` انجام پذیرد.
3. **عدم هاردکد پورت:** هیچ پورتی نباید به‌صورت هاردکد (Hardcoded) متوقف بر عدد ۲۲۲۲ باشد و حتماً باید متغیر `SEC_SSH` رعایت شود.
4. **بروزرسانی شماره نسخه:** در صورت انتشار نسخه رسمی روی `main`، مقدار متغیر `SCRIPT_VERSION` و هدر اسکریپت را هماهنگ نگه دارید.
