# 🚀 PG Node SSH Tunnel Manager (`v7.8`)

ابزار خط فرمان و خودکار برای راه‌اندازی و مدیریت **تانل معکوس SSH در بستر `TLS 1.3` به سبک `Trojan` همراه با استتار واقعی وب (`Active-Prober Proof`)** میان **پنل PasarGuard (سرور ایران)** و **نود خارج** — با کانال‌های موازی مستقل، رمزنگاری سخت‌افزاری، Watchdog انتها-به-انتها و مجموعه‌ی کامل ابزارهای نگهداری.

---

## ✨ ویژگی‌ها و قابلیت‌های کلیدی

### 🕵️ استتار و ضد DPI
- **استتار کامل WebSocket (`HTTP/1.1 101 Switching Protocols`):** بعد از تایید کلید مخفی، سرور ایران پاسخ استاندارد و واقعی `101` همراه با `Sec-WebSocket-Accept` محاسبه‌شده مطابق `RFC 6455` ارسال می‌کند؛ ترافیک حتی برای دارندگان کلید، دقیقاً یک اتصال `WebSocket` معمولی به نظر می‌رسد. مسیرهای طبیعی تصادفی (`/api/v2/stream` و...) و `User-Agent`های واقعی مرورگرها.
- **مورفینگ ترافیک (`TLS Record Morphing + Coalescing`):** رکوردهای `TLS` در بازه‌ی تصادفی `1KB تا 16KB` شکسته می‌شوند و پکت‌های کوچک در پنجره‌ی `2-15ms` ادغام می‌گردند — هیچ امضای طولی یا زمانی ثابتی باقی نمی‌ماند (سربار < `0.01%`).
- **ضد Active-Prober به سبک Trojan + استتار وب واقعی:** سرور ایران هیچ بایتی را پیش‌دستانه ارسال نمی‌کند؛ بدون کلید مخفی (`TLS_SECRET`) هر اسکنر/مرورگر مستقیماً به وب‌سرور واقعی محلی هدایت شده و پاسخ `HTTP` واقعی می‌گیرد (Zero SSH Banner Leak).
- **گواهی معتبر `Let's Encrypt` با تشخیص خودکار:** اسکن خودکار والیوم‌های Docker کدی، `Certbot` و `acme.sh` + همگام‌سازی ساعتی گواهی.
- **سازگاری دوطرفه با نسخه‌ی `v6.x`:** کلاینت قدیمی بدون `101` هم کار می‌کند؛ آپدیت دو سرور با هر ترتیبی امن است.

### ⚡ سرعت و پینگ
- **کانال‌های موازی مستقل:** پورت مدیریت نود و هر پورت دیتا، هر کدام یک سرویس `systemd` مجزا با ری‌استارت خودکار `3` ثانیه‌ای دارند؛ قطعی یک کانال هرگز بقیه را مختل نمی‌کند.
- **استخر `BIND_IPS` با انتخاب هوشمند:** توزیع کانال‌ها بین IPهای تمیز + Failover چسبیده به آخرین IP سالم؛ هنگام reconnect کاندیداها با پروب سریع TCP رتبه‌بندی و کم‌RTT‌ترین با هیسترزیس ۲۰٪ انتخاب می‌شود (`Latency-Aware`).
- **رمزنگاری سخت‌افزاری + انتخاب رمز بر اساس CPU:** با AES-NI از `aes128-gcm` و بدون آن از `chacha20-poly1305` + `Compression=no`.
- **بهینه‌سازی کرنل (Option 4):** `TCP BBR + fq`، محدودسازی Bufferbloat با `tcp_notsent_lowat=131072` (بهبود ۳۰-۵۰٪ پینگ زیر لود)، پخش `RPS` روی هسته‌ها + یونیت بوت `pg-tunnel-net-tune` و بازگردانی خودکار توسط کرون.
- **Keepalive های تنگ‌شده:** `ServerAliveInterval 10/15s × 2` → تشخیص قطعی نیمه‌باز در ~۲۰-۳۰ ثانیه.

### 🐶 پایداری
- **Watchdog انتها-به-انتها (سرور ایران):** پایش ۱۵ ثانیه‌ای لیسنرها و جلسه‌های TLS + خودترمیمی محافظه‌کارانه (حداکثر یک ری‌استارت wrapper در ۱۰ دقیقه، فقط در حالت قفل کامل) — بدون regex و بدون هیچ هشداری در لاگ.
- **کرون‌جاب خود-ترمیم بدون قطعی (Other Options ⬅ 2):** اجرای ساعت‌به‌ساعت با دقیقه‌های یکی-در-میان روی دو سرور؛ فقط سرویس‌های خاموش را احیا می‌کند، تانل‌های سالم و کارت شبکه را لمس نمی‌کند (مسیر کرون فقط چند sysctl را تایید می‌کند).
- **آزادسازی آنی پورت زامبی:** پیش از هر اتصال مجدد، فقط پورت همان کانال آزاد می‌شود (لیسنرهای کانال‌های سالم دست نمی‌خورند).
- **موتور غیرمسدودکننده‌ی تک‌رشته‌ای (`MemoryBIO`):** انتقال فول-دوپلکس پرسرعت بدون قفل‌شدگی.

### 🔐 امنیت
- **TOFU Host-Key Pinning:** کلید Host سرور ایران در `/etc/pg-tunnel/known_hosts` پین می‌شود؛ حتی با شکست فرضی TLS، لایه‌ی SSH در برابر MITM مقاوم می‌ماند (بعد از نصب مجدد ایران: `pg-tunnel reset-hostkey`).
- **سرور استتار ایران با کاربر غیر root + Sandbox:** کاربر اختصاصی `pg-tunnel` با فقط ۳ قابلیت لازم + `ProtectSystem=strict` + `NoNewPrivileges` — حتی باگ فرضی پایتون به root نمی‌رسد.
- **چرخش بدون قطعی سکرت (Other Options ⬅ 4):** سرور ایران هر دو کلید قدیم و جدید را تا ۲۴ ساعت می‌پذیرد؛ بعد از آپدیت خارج، کلید قدیم Finalize می‌شود — بدون حتی ۱ ثانیه قطعی.
- **سپر کرنلی Brute-Force پورت ۲۲ (Other Options ⬅ 3):** حداکثر `8` اتصال جدید در `60` ثانیه به ازای هر IP (loopback و نشست‌های جاری معاف) + مقاوم‌سازی خودکار `sshd` (`MaxStartups 150:30:300`).
- **حسابداری ترافیک خود-تمیزشونده:** شمارنده‌های per-IP در `iptables mangle`؛ IPهای بی‌ترافیک (اسکنرهای اینترنت مانند Censys/Shodan) خودکار حذف و همگام‌سازی جراحیِ قوانین، شمارنده‌ی IPهای سالم را هرگز ریست نمی‌کند.

### 🛠️ مدیریت و دیده‌بانی
- **داشبورد زنده‌ی تک‌صفحه‌ای (Option 2):** سرعت لحظه‌ای، مصرف تجمعی، وضعیت هر کانال، مصرف تفکیک‌شده‌ی هر IP، وضعیت Watchdog/سپر/کرون، خط Kernel Tuning و رول‌های NAT.
- **آپدیتر مستقیم شاخه/کامیت (Option 5):** دریافت آخرین کامیت هر شاخه یا SHA بدون نیاز به PR/Merge — آپدیت اسکریپت صفر-قطعی است.
- **تعمیر سریع (Option 6):** بازسازی سرویس‌ها و رول‌ها از روی کانفیگ ذخیره‌شده.
- **تعویض امن IP نود (Other Options ⬅ 6):** فقط خط `OUT_IP` عوض و رول‌های REDIRECT هدفمند بازسازی می‌شوند — بدون دست زدن به کلید/سکرت/گواهی/سرویس‌ها.
- **بکاپ/ریستور امن (Other Options ⬅ 5):** خروجی `tar` با اعتبارسنجی مسیرها هنگام Restore (رد خودکار آرشیو آلوده).
- **حذف ایمن (Option 3):** فقط سرویس‌ها/رول‌ها/فایل‌های اختصاصی پروژه؛ Docker و SSH و رول‌های بی‌ربط دست‌نخورده می‌مانند.

## 🗺️ معماری و نقش IPها (مهم!)

```text
کاربران ──(کانفیگ تانل)──► IP ایران : پورت ──► پنل ──► آدرس نود ──► تانل TLS ──► نود خارج ──► اینترنت
کاربران ──(دایرکت / CDN)──► IP رو-به-کاربرِ سرور خارج
سرور خارج ──(کانال‌های تانل، مبدا از BIND_IPS)──► IP ایران : 2087
```

| نقش IP | کجا تعریف می‌شود | چه ترافیکی می‌کشد | اگر فیلتر شود |
| :--- | :--- | :--- | :--- |
| **استخر بایند** (`BIND_IPS`) | سرور خارج، Option 1 | فقط ارتباط سرور→ایران (TLS استتار‌شده، کم‌حجم) | کانال‌ها به IP دیگر استخر Failover می‌کنند |
| **IP نود / `OUT_IP`** | سرور ایران، Option 1 یا Other Options ⬅ 6 | مسیر پنل→نود توسط رول‌های REDIRECT **داخل خود ایران** به تانل برمی‌گردد (شامل پورت مدیریت از v7.6) — هیچ بایتی به سمت این IP از ایران خارج نمی‌شود | کانفیگ‌های تانل و پنل **ادامه می‌یابند**؛ فقط دایرکت (اگر همان IP باشد) می‌میرد |
| **IP دایرکت کاربران** | پنل (این‌باوند نود خارج) | ترافیک واقعی کاربران | طبق طراحی — تنها IP فدایی؛ تعویض ۵ دقیقه‌ای |

**قوانین طلایی:**
1. آدرس نودها در پنل یا `127.0.0.1` باشد (ساده‌ترین و مطمئن‌ترین) یا دقیقاً همان `OUT_IP`.
2. IP دایرکت کاربران **هرگز** وارد `BIND_IPS` نشود — هر IP فقط یک نقش داشته باشد.
3. فیلتر شدن IP رو-به-کاربر فقط دایرکت را می‌کشد؛ تانل، CDN و مسیر پنل مصون‌اند.

## 🛠️ نصب و راه‌اندازی سریع

### پیش‌نیازها
- سیستم‌عامل **Ubuntu 20.04 / 22.04 / 24.04** یا **Debian 11 / 12** با دسترسی `root`
- تنظیم آدرس نود خارج در پنل PasarGuard روی `127.0.0.1` و پورت مدیریت نود (مثلاً `62075`)

### دستور نصب اولیه روی هر دو سرور (ایران و خارج)

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/XiliService/pg-node-ssh-tunnel/main/script.sh)
```

پس از اولین اجرا، ابزار به صورت سراسری نصب شده و از هر مسیر با دستور `pg-tunnel` قابل اجراست.

## 📖 مراحل راه‌اندازی گام‌به‌گام

### گام ۱: پیکربندی سرور ایران (`Main / Panel Server`)
1. دستور `pg-tunnel` را اجرا کرده، گزینه‌ی **`1`** و سپس **`1) Iran Server`** را انتخاب کنید.
2. مقادیر زیر را وارد نمایید (با وجود تنظیمات قبلی، مقادیر فعلی پیش‌فرض‌اند):
   - **`Foreign Server IP`:** IP نود خارج (برچسب `OUT_IP` — ترافیک پنل به سمت آن، داخل خود ایران به تانل redirect می‌شود).
   - **`Node management port`:** پیش‌فرض `62075`.
   - **`Outbound data ports`:** پورت‌های دیتای تانل جداشده با کاما (مثلاً `64483,26132,22971`).
   - **`Anti-DPI HTTPS Port`:** پیش‌فرض `2087`.
   - **`TLS Cover Domain (SNI)`:** دامنه‌ی واقعی که به طور خودکار از گواهی شناسایی می‌شود (فقط `Enter`).
   - **`Anti-Prober Secret Key`:** کلید تولیدی خودکار (فقط `Enter`).
3. خلاصه‌ی مشخصات (`IP` / `TLS Port` / `SNI` / `Secret`) برای ورود در سرور خارج نمایش داده می‌شود.

### گام ۲: پیکربندی سرور خارج (`Foreign Node Server`)
1. `pg-tunnel` ⬅ گزینه‌ی **`1`** ⬅ **`2) Foreign Server`**.
2. مشخصات نمایش‌داده‌شده در سرور ایران را به همراه پورت نود و پورت‌های دیتا وارد کنید.
3. در **`Source Bind IPs`** فقط IPهایی را وارد کنید که نقش تانل دارند (IP رو-به-کاربر هرگز!) — یا برای حالت خودکار خالی بگذارید.
4. با کلید ثبت‌شده‌ی قبلی، اتصال بدون رمز و در کمتر از ۲ ثانیه برقرار می‌شود.

## 🔄 آپدیت

- **روش عادی:** `pg-tunnel` ⬅ گزینه‌ی **`5`** — در صورت پایین‌تر بودن نسخه‌ی `main` یا نیاز به شاخه‌ی توسعه، نام شاخه یا SHA را وارد کنید. آپدیت فقط فایل اسکریپت را عوض می‌کند (صفر-قطعی) و فیکس‌های خودکار (مثل رول پورت مدیریت) در اولین اجرا اعمال می‌شوند.
- **وقتی GitHub از سرور ایران در دسترس نیست:** از سرور خارج (که آپدیت شده) فایل را منتقل کنید:

```bash
# روی سرور خارج:
scp /usr/local/bin/pg-tunnel root@<IRAN_IP>:/tmp/pg-new
# روی سرور ایران:
install -m 755 /tmp/pg-new /usr/local/bin/pg-tunnel && rm -f /tmp/pg-new
# تأیید یکسان بودن هر دو سرور:
md5sum /usr/local/bin/pg-tunnel
```

## 🤖 قوانین معماری و توسعه

1. تمامی متون، پیام‌ها و کامنت‌های داخل `script.sh` باید ۱۰۰٪ انگلیسی (ASCII خالص) باشند.
2. هرگز کل جدول NAT فلاش نشود و فقط قوانین هدفمند پروژه با `-C` / `-A` / `-D` مدیریت شوند.
3. هرگز پروسه‌ی اصلی SSH به صورت اجباری متوقف نشود؛ مدیریت فقط با `systemctl reload/restart ssh.service` انجام شده و `Port 22` حفظ گردد.
4. هیچ نام شاخه‌ی کاری یا هش کامیت به صورت ثابت در کد یا فایل وضعیت روی دیسک ذخیره نشود.
