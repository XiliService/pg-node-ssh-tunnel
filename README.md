# اسکریپت مدیریت تونل معکوس SSH برای نودهای پاسارگاد

این پروژه جهت ایجاد و مدیریت اتصالات تونل معکوس (Reverse SSH Tunnel) پایدار بین سرورهای ایران و خارج، به‌ویژه برای اتصال نودهای پنل پاسارگاد (Pasarguard) طراحی شده است.

این اسکریپت به‌صورت خودکار بر روی لینوکس نصب شده و دستور سیستماتیک `pg-tunnel` را در اختیارتان قرار می‌دهد.

---

## 🚀 نصب سریع (دستور یک‌خطی)

برای نصب یا اجرای مستقیم آخرین نسخه اسکریپت از مخزن گیت‌هاب، دستور زیر را در ترمینال سرور (با دسترسی root یا sudo) وارد کنید:

```
sudo curl -fsSL https://raw.githubusercontent.com/XiliService/pg-node-ssh-tunnel/main/script.sh -o /usr/local/bin/pg-tunnel && sudo chmod +x /usr/local/bin/pg-tunnel && sudo pg-tunnel
```

پس از اولین اجرا، اسکریپت روی سرور ثبت شده و در دفعات بعدی فقط کافیست دستور زیر را بزنید:
```
pg-tunnel
```

## 📌 راهنمای استفاده سریع

### ۱. تنظیم سرور ایران
1. اسکریپت را با دستور `pg-tunnel` اجرا کنید.
2. گزینه `1` (Install / Configure Tunnel) و سپس گزینه `1) Iran Server` را انتخاب کنید.
3. اطلاعات زیر را وارد کنید:
   - **آی‌پی سرور خارج** (آی‌پی خروجی سرور خارج که در پاسارگاد ثبت شده).
   - **پورت‌های دیتا** (با کاما جدا شده، مانند: `64483,26132,22971`).
   - **پورت SSH ثانویه دلخواه** (مثلاً `2222` یا `8543`).

### ۲. تنظیم سرور خارج
1. اسکریپت را در **سرور خارج** اجرا کنید.
2. گزینه `1` را زده و سپس `2) Foreign Server` را انتخاب کنید.
3. اطلاعات زیر را وارد کنید:
   - **آی‌پی سرور ایران**.
   - **پورت SSH ثانویه سرور ایران** (همان پورتی که در مرحله قبل تعریف کردید).
   - **پورت مدیریت نود** (مانند: `62075`).
   - **پورت‌های دیتا** (همان پورت‌های مرحله قبل).
4. رمز عبور سرور ایران را یک‌بار وارد کنید تا کلید SSH به‌صورت خودکار منتقل شده و سرویس دائم تشکیل شود.

## 🤖 مستندات فنی و ساختار اسکریپت (مخصوص AI Agents و توسعه‌دهندگان)

> **توجه برای ایجنت‌های هوش مصنوعی (AI Agents):**  
> اگر در یک نشست جدید در حال توسعه یا اصلاح این مخزن هستید، لطفاً الزامات و ساختارهای زیر را کاملاً حفظ کنید تا عملکرد تونل یا داکر سرورها مختل نشود.

### ۱. معماری و منطق کاری (Architecture)
* **پورت SSH ثانویه (Secondary SSH Port):**  
  اسکریپت پورت اصلی ۲۲ را **هرگز حذف نمی‌کند**. پورت ثانویه سفارشی (مثلاً ۲۲۲۲) فقط کنار پورت ۲۲ اضافه می‌شود تا تونل معکوس از طریق آن برقرار شود و اختلالات DPI روی پورت ۲۲، تونل را قطع نکند.
* **مدیریت SSH در اوبونتو (`ssh.socket` vs `ssh.service`):**  
  در توزیع‌های جدید اوبونتو، `ssh.socket` باعث خرابی لیسن کردن روی پورت‌های چندگانه و خطا در systemd می‌شود. اسکریپت به‌صورت اجباری `ssh.socket` را `mask` کرده و مستقیماً از `ssh.service` استفاده می‌کند.
* **ترافیک و بازهدایت iptables در ایران:**  
  سرور ایران ترافیک خروجی به سمت آی‌پی خارج را با رول زیر به پورت‌های لوکال‌بایند شده هدایت می‌کند:
  `iptables -t nat -A OUTPUT -p tcp -d OUT_IP --dport PORT -j REDIRECT --to-ports PORT`
  *⚠️ **قانون حیاتی:** هرگز نباید جدول NAT با دستور `iptables -t nat -F` پاکسازی (Flush) شود! این کار شبکه Docker و پل‌های شبکه پاسارگاد را می‌کشد. حذف رول‌ها باید حتماً به‌صورت Targeted با سوئیچ `-D` انجام شود.*

### ۲. پایدارسازی سرویس در سرور خارج (Systemd Service)
سرویس `/etc/systemd/system/reverse-tunnel.service` روی سرور خارج ساخته می‌شود.  
پارامترهای کلیدی SSH در این سرویس عبارتند از:
- `-o ServerAliveInterval=30` و `-o ServerAliveCountMax=3`: جهت تشخیص قطعی اتصال و بازسازی آن.
- `-o ExitOnForwardFailure=yes`: در صورت اشغال بودن پورت، پروسه متوقف شده تا systemd آن را Restart کند.
- `Restart=always` و `RestartSec=8`: تلاش مجدد بی‌نهایت برای وصل ماندن تونل.

### ۳. ذخیره‌سازی کانفیگ‌ها و قابلیت Update / Repair
* کانفیگ‌ها در مسیر `/etc/pg-tunnel/iran.conf` و `/etc/pg-tunnel/foreign.conf` ذخیره می‌شوند.
* **گزینه ۶ (Update):** آخرین نسخه اسکریپت را مستقیم از `raw.githubusercontent.com` دریافت و جایگزین `/usr/local/bin/pg-tunnel` می‌کند.
* **گزینه ۷ (Repair):** بدون نیاز به دریافت مجدد IPها از کاربر، متغیرها را از فایل کانفیگ خوانده و سرویس‌ها را ریستارت و ترمیم می‌کند.

### ⚠️ الزامات سخت‌گیرانه برای توسعه‌دهندگان بعدی:
1. **زبان اسکریپت:** تمامی متون، پرامپت‌ها، لاگ‌ها و پیام‌های داخل اسکریپت `script.sh` باید **۱۰۰٪ انگلیسی** باقی بمانند.
2. **عدم قطع دسترسی:** از دستوراتی مانند `killall sshd` استفاده نکنید. ریستارت سرویس‌ها باید همیشه از طریق `systemctl restart ssh.service` انجام پذیرد.
3. **عدم هاردکد پورت:** هیچ پورتی نباید به‌صورت هاردکد (Hardcoded) متوقف بر عدد ۲۲۲۲ باشد و حتماً باید متغیر `SEC_SSH` رعایت شود.
